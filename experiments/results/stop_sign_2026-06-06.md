# Stop-sign R22 retest + R12 decomposition (2026-06-06, v0.11.0)

The v0.5.18 cross-family paraphrase-axis sweep against the stop-sign benchmark (`stop_sign_2026-05-18.md`) was the minimal end-to-end demonstration of the methodology at v0.5 framework. It lacked two pieces of methodological scaffolding the framework has since gained:

- **R22 test-retest evidence** for any of the captured models. The v0.5.18 sweep was a single capture per model per paraphrase variant.
- **R12 under-powered decomposition rendering** on the by-tag cells. The stop-sign benchmark is structured around small per-tag subsets (1–2 items each); v0.8.0 introduced an explicit `[under-powered: n < 10]` annotation precisely for cells like these, and v0.5.18 predates that fix.

This analysis backfills both — using `infereval retest --auto` (v0.11.0+) to capture R22 evidence for three representative models, and the v0.8.0 decomposition rendering to show how the framework now reads the stop-sign by-tag cells. The paraphrase-axis findings from v0.5.18 are unchanged; this is methodological scaffolding, not a new substantive sweep.

## Setup

- **Benchmark**: `examples/stop_sign/benchmark.json` (the paper's Example 1). n=4, m=1, paper-aligned. Analyst row: `[good, good, good, bad]`. Unchanged.
- **R22 capture parameters**: `--n-samples 3 --temperature 0.0 --max-tokens 1024 --interval-s 0`. Back-to-back captures; see the "What back-to-back captures and what it doesn't" section below.
- **Capture harness**: `experiments/scripts/stop_sign_r22_captures.sh`. ~72 LLM calls total across 3 models × 4 items × 3 samples × 2 captures.
- **Models** (one flagship per family — the same panel from v0.5.18, narrowed to the cross-family-distinct three):

| Model | Provider | Wall time (both captures) |
|---|---|---:|
| Claude Opus 4.7 | anthropic | ~25s |
| GPT-4.1 | openai | ~15s |
| Gemini 2.5 Pro | openrouter | ~30s |

Output: `experiments/results/stop_sign/retest/{opus47,gpt41,gemini25pro}/{eta-a,eta-b}.{json,run.jsonl}` + `{opus47,gpt41,gemini25pro}-retest.json`.

## R22 retest table

| Model | n agreement | flip rate | test-retest κ | stability_verdict |
|---|---:|---:|---:|---|
| Claude Opus 4.7 | 4/4 | 0.0% | **+1.0000** | stable |

**All three models produce perfectly-stable retests at the back-to-back interval.** Each model returned the same per-item majority verdict twice in a row. Zero flips, perfect agreement, κ = +1.0 (the maximum the test-retest formula admits), `stability_verdict = "stable"`.

This is informative but not the dramatic result the v0.10.0 pulmonology rerun produced. The next section unpacks why.

## What `--interval-s 0` captures, and what it doesn't

The v0.10.0 pulmonology cross-family rerun found Gemini 2.5 Pro shifting κ_C by **0.21** across captures 2.5 weeks apart with identical params. The v0.11.0 stop-sign R22 capture finds zero spread across back-to-back captures. Both numbers are correct and both are informative — they capture different things:

- **`--interval-s 0` (back-to-back)** measures *within-session* stochasticity: sampling noise from `n_samples=3`, server-side load-balancing across replicas, transient network or batch effects. On items that lie comfortably in the model's training distribution (which the stop-sign items do), this floor is essentially zero.
- **Longer intervals** measure cumulative across-session effects: silent provider weight updates, cache invalidation, model deprecation, training-data freshness shifts. The pulmonology Gemini drift was an instance of this class.

The stop-sign perfect-stability result therefore **confirms** the v0.10.0 reading rather than contradicting it. If the back-to-back floor were non-zero on a stable benchmark, the v0.10.0 drift could plausibly be sampling noise inflated by item count or item ambiguity. The fact that the floor *is* zero on a 4-item canonical benchmark makes the v0.10.0 finding methodologically clean: that 0.21 κ_C shift cannot be back-to-back sampling noise, because back-to-back sampling noise is zero. It is genuinely cross-capture.

The right reading of the v0.11.0 stop-sign R22 evidence is therefore:

> The framework's default `--interval-s 0` retest measures one component of variance (within-session); achieving κ = +1.0 against the 4-item paper-aligned demo is a *baseline* that lets longer-interval captures be interpreted cleanly. The methodologically interesting question — does the model's behavior drift across days or weeks — requires explicit longer-interval `--interval-s N` captures that v0.11.0 makes operationally trivial but does not itself ship.

A natural v0.11.x or v0.12.0 follow-up: a multi-interval auto-retest mode (`--interval-s 0 --interval-s 86400 --interval-s 604800` to capture back-to-back / next-day / next-week variance in one orchestrated run). Out of scope here.

## R12 under-powered decomposition rendering

The stop-sign benchmark is the canonical small-n case for v0.8.0's under-powered guard. Every by-tag cell is n=1 or n=2 — well below the `MIN_K_FOR_SUBSAMPLING_CI = 10` threshold. Here is the v0.8.0+ rendering against Opus 4.7's capture A:

```text
Overall
=======
n (items)              : 4
coverage (M)           : 1.0000
κ_C(η, consensus)       : +1.0000
κ_F(η)                 : +1.0000
κ_F*(β) (inter-analyst, all): undefined

By tag: base-inference
======================
n (items)              : 1
n (substantive)        : 1
M verdicts             : good 1 / bad 0 / abstain 0
reference verdicts     : good 1 / bad 0 / abstain 0
κ_C(η, consensus)       : undefined  [under-powered: n < 10]
κ_F(η)                 : undefined  [under-powered: n < 10]

By tag: irrelevant-addition
===========================
n (items)              : 2
n (substantive)        : 2
M verdicts             : good 2 / bad 0 / abstain 0
reference verdicts     : good 2 / bad 0 / abstain 0
κ_C(η, consensus)       : undefined  [under-powered: n < 10]
κ_F(η)                 : undefined  [under-powered: n < 10]

By tag: defeater
================
n (items)              : 1
n (substantive)        : 1
M verdicts             : good 0 / bad 1 / abstain 0
reference verdicts     : good 0 / bad 1 / abstain 0
κ_C(η, consensus)       : undefined  [under-powered: n < 10]
κ_F(η)                 : undefined  [under-powered: n < 10]
```

Two things to read out of this rendering:

1. **The `[under-powered: n < 10]` annotation fires on every by-tag cell.** Each cell has n_substantive ∈ {1, 2}, which is exactly the case v0.8.0 was authored to handle. The framework's correct posture on cells this small is "this κ value, even when defined, isn't a measurement — you cannot generalize from it." The annotation makes that visible at the surface where the reader looks at the number. An analyst's correct action on these cells is to inspect the M and reference verdict counts and read the *direction* (perfect agreement here), not the *magnitude*.
2. **The Overall κ_C = +1.0** for this capture is defined and meaningful (n=4 substantive items with full coverage and perfect agreement against the analyst). It is also above the under-powered threshold — actually it isn't (n=4 < 10), but v0.8.0 only gates by-tag/by-rsr-target cells, not the headline. The methodology paper's discussion of the stop-sign result should note this asymmetry explicitly: the *headline* is still readable as evidence (with appropriate caveats about a 4-item benchmark), but the *by-tag decomposition* is, on cells this small, a diagnostic-direction lead at most.

This is the v0.8.0 fix landing on the canonical case it was designed for. The paper-aligned demo finally renders with the under-powered guard that v0.5.18 predates.

## Comparison to v0.5.18 paraphrase-axis findings

The v0.5.18 cross-family sweep at `stop_sign_2026-05-18.md` is unchanged. Its three δ(ra) variants (`original` / `intrinsic` / `perceptual`) produced the carving-relativity result the paper §5 reports: most models score +1.0 against the analyst on `original` and `intrinsic` but drop to +0.20–+0.50 on `perceptual`. That is a finding about the **structure of the variant axis**, and is unaffected by what v0.11.0 adds.

What v0.11.0 supplements:

| v0.5.18 surface | v0.11.0 supplement |
|---|---|
| κ_C against analyst across 3 δ variants, 13 models | + R22 test-retest κ for 3 representative models on `original` |
| Per-item verdict table for each (model, variant) pair | + R12 under-powered annotation on the by-tag cells |
| Methodology framework: v0.5.x (pre-R22, pre-R12 guard) | + v0.11.0 framework (R22 auto-retest, R12 under-powered guard, R22 second leg / identity criterion from v0.6.1) |

A v0.12+ refresh of the full 13-model sweep against the v0.11.0 framework would be a substantial undertaking and is deliberately out of scope. The supplement here is on the **canonical models the paper §5 anchors to** and on the **methodological scaffolding the framework now applies by default**.

## What this evidence does and does not justify

**Does justify** (in the paper §5 discussion):

- The paper-aligned demo's κ_C = +1.0 against `original` δ(ra) for the named flagship models is **stable on back-to-back retest** at framework v0.11.0. The within-session reliability floor is zero on this benchmark; the headline κ is not a single-draw artifact of sampling noise.
- The framework's posture on small-n by-tag cells is now explicit: cells with n_substantive < 10 are rendered with `[under-powered: n < 10]`. Analysts reading the stop-sign decomposition cannot mistake the per-tag κ for a measurement; the framework forces the small-n caveat onto the surface.

**Does not justify**:

- A claim about cross-update stability — for that we'd need the longer-interval `--interval-s N` captures discussed above, which v0.11.0 makes operationally trivial but does not ship.
- A claim that the models named here are *generally* stable on inferential-mastery probing — stop-sign items are deliberately canonical; the pulmonology v0.10.0 finding (Gemini's 0.21 drift) shows that dialectical-medium items can yield very different stability profiles. The right reading is benchmark-specific.

## Reproducibility

The committed artifacts at `experiments/results/stop_sign/retest/` were generated by:

```sh
# Set the API keys
export ANTHROPIC_API_KEY=...
export OPENAI_API_KEY=...
export OPENROUTER_API_KEY=...

# Run the harness
experiments/scripts/stop_sign_r22_captures.sh
```

Each per-model RetestResult JSON is the canonical artifact; the per-capture eta and run.jsonl files are the audit-grade reproducibility evidence. v0.11.0 wires `--save-etas DIR` to keep these by default for the bundled stop-sign capture.

## Caveats unchanged from v0.5.18

1. **m = 1.** Single-analyst panel; `κ_F*` undefined per Remark 4.
2. **Placeholder demo.** The stop-sign benchmark is a methodology demonstration, not a leaderboard. Numbers describe the framework producing coherent values.
3. **4 items.** Even with `[under-powered]` annotations applied, the *headline* κ on a 4-item benchmark is itself a small-n result with all the caveats that implies. The paper's worked example uses it for *pedagogy*, not *measurement claims*.
